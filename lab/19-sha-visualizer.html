Theory — avalanche behaviour

A cryptographic hash maps any message to a fixed 256-bit fingerprint. Its defining property, the avalanche effect: flip one input bit and roughly half the output bits flip, unpredictably. This bench measures that property directly.

1 · Padding — any message to 512-bit blocks

pad(msg): append 0x80, zeros, then 64-bit big-endian message length → total length ≡ 0 (mod 512)

The message becomes N blocks of sixteen 32-bit words W[0..15].

2 · Message schedule — 16 words stretched to 64

σ₀(x) = ROTR⁷(x) ⊕ ROTR¹⁸(x) ⊕ SHR³(x) σ₁(x) = ROTR¹⁷(x) ⊕ ROTR¹⁹(x) ⊕ SHR¹⁰(x) W[t] = σ₁(W[t−2]) + W[t−7] + σ₀(W[t−15]) + W[t−16] (mod 2³²)

Rotations pull old bits into new words. Local change starts to spread here.

3 · Compression — 64 mixing rounds

Σ₀ = ROTR²(e)⊕ROTR¹³(e)⊕ROTR²²(e) Σ₁ = ROTR⁶(e)⊕ROTR¹¹(e)⊕ROTR²⁵(e) ch = (e ∧ f) ⊕ (¬e ∧ h) maj = (a∧b) ⊕ (a∧c) ⊕ (b∧c) T₁ = h + Σ₁ + ch + K[t] + W[t] T₂ = Σ₀ + maj (a,b,c,d,e,f,g,h) ← (T₁+T₂, a, b, c, d+T₁, e, f, g)

Additions mod 2³² carry; carries propagate; every round feeds the next. After 64 rounds the eight working registers blend the entire message.

4 · The avalanche

Δ = digestA ⊕ digestB → 256 bits expected |Δ| ≈ 128 (binomial n=256, p=½, σ≈8)

Two near-identical messages are hashed, the digest bit-planes XORed, and the result painted 16×16. Around 128 lit cells: the algorithm is doing its work. Flip a bit repeatedly and watch the verdict move around the ideal. Measured randomness.

5 · The vault wall

The bit-plane is rendered as a raised wall of drawers: agreeing bits sit recessed in dark sockets, disagreeing bits rise — bright copper where the digest bit is 1, deep copper where it is 0 — depth-sorted back to front. The wall hangs on a gimbal: drag to turn it (it coasts when released), scroll to lens, and it sways on its own when idle. The sweep lifts the wall row by row.

6 · SHA-1, the degraded variant

Same Merkle–Damgård shape: 80 rounds, five 32-bit registers, four mixing functions per step. Its avalanche reads healthy on this bench. The known weakness is theoretical collision attacks — hence 256-bit digests as the default.

Spec — build record

One self-contained HTML file, zero dependencies. Both hash cores are written in this page — plain JavaScript on 32-bit words, no WebCrypto. Nothing about the computation is hidden.

Inside

  • sha256(msg) — padding, 64-word message schedule, 64-round compression, 8-word state; checked against the standard vectors (empty string, "abc", the 55/56-byte block boundary).
  • sha1(msg) — 80-round variant with the four-step f/g mixing functions, also vector-checked.
  • Diff engine — per-digit hex diff marking, 256/160-bit XOR bit-plane, Hamming distance, animated sweep reveal.
  • Vault wall — one drawer per digest bit, raised where the two digests disagree; tone carries bit value; drag/scroll gimbal with inertia and idle sway.
  • Reduced motion — prefers-reduced-motion paints the final state immediately, no sweep.

Interactions

  • Type into either box — both digests recompute live per keystroke.
  • Flip bit — F flips one uniformly chosen bit of message B in place; the avalanche re-rolls.
  • Space halt · R reset inputs · N roll the pair.
  • Algorithm selector: SHA-256 / SHA-1 / Both. Sweep fader scales the reveal.
  • State (texts, algorithm, sweep) persists in the URL hash for sharing.

Budget

Hashing a short message costs a few microseconds. The bench re-hashes per keystroke and idles below 1% CPU; the animation budget goes to the reveal, not the math.
