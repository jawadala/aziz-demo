PRINCIPLE

A plant is a sentence. Small alphabet, start word, a handful of rewrite rules; the string replaces itself generation by generation. The turtle reads the final word with a nib. Iteration depth plays the role of time. Nothing is drawn until the language stops expanding.

FORMULATION

A grammar is the tuple G = (V, ω, P, δ)

  • V — alphabet (F, X, +, −, [, ] …)
  • ω — axiom, the starting string, e.g. X
  • P — productions: X → F+[[X]−X]−F[−FX]+X, applied to every symbol in parallel each generation
  • δ — the turn angle applied to + and −

One generation rewrites every symbol simultaneously: ω ⇒ g₁ ⇒ g₂ ⇒ … ⇒ g_n. Symbols with no production survive untouched — leaves (X) mark spots for future growth while wood (F) accumulates behind them.

The turtle carries a state (x, y, α):

F : (x,y) → (x + L·cos α, y + L·sin α) — draw + : α ← α + δ − : α ← α − δ [ : push state ] : pop state

Brackets give the turtle a memory of the branch point; one string encodes an entire tree topology. The finished sheet is mounted on a tilted turntable — drag turns it, the wheel tilts it. Strokes pale and thin by bracket depth: trunk dark and wide, twigs bright and fine. Space-filling curves are plants with no brackets.

SERVICE DATA

  • Single file. No dependencies, no fonts, no images, no network calls.
  • Deterministic parallel string rewriting, plain JS. Turtle walk emits segments bucketed by bracket depth.
  • Pseudo-3D: planar rotation plus tilt projection, ordered by depth bucket.
  • Renderer batches one canvas path per depth level — 50k+ segments stroke in a few draw calls.
  • Growth reveals segments in depth order: trunk before twigs. Auto-turn after 3.2 s idle.
  • Auto-fit: turtle bounding box mapped to viewport; MAGNIFY multiplies on top.
  • Editors are live; state persists in the URL hash via LINK, turntable included.
  • String and segment caps with a notice keep hostile rule sets from locking a tab.
  • prefers-reduced-motion skips the growth animation and shows the full specimen.
