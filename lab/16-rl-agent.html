TABULAR Q-LEARNING

No teacher. Q starts at zero. Act, observe reward, update one entry. Repeated updates turn the table into a value map.

1 · STATES, ACTIONS, REWARDS

state s = current cell (24×16 = 384 states) action a = ↓ up ← right (4 actions) reward r = goal (+1.0) · trap (−1.0) · step (−0.04)

r_step < 0: longer routes cost more; optimal policy prefers short routes.

2 · THE UPDATE RULE

Q(s,a) ← Q(s,a) + α · [ r + γ · max Q(s′,·) − Q(s,a) ] └────── TD error δ ──────┘

δ = outcome (r plus discounted max at s′) minus prediction. α scales the correction, γ the credit back:

  • α — 0.05: slow, stable. 0.99: values oscillate.
  • γ — 0.5: value spreads ~2-3 cells. 0.99: across the map.
  • ε — probability ε: uniform random action; else argmax Q.
π(s) = argmax Q(s,·) ← greedy policy, drawn as arrows

3 · FAILURE MODES

  • ε = 0 before first goal — greedy from a zero table follows noise; may never reach the goal.
  • α at max — values oscillate. γ near 0.5 — value stops spreading beyond 2-3 cells.
  • Wall painted across a learned route — stale Q-values persist until re-training reroutes.

BUILD RECORD

Single self-contained HTML file. No frameworks, no CDNs, no fonts, no build step. Tabular RL stack: agent, environment, reward function, display.

ENGINEERING NOTES

  • Q-table: Float32Array cells×4. Env returns (s′, r, done); terminals: goal, trap, cliff, step cap.
  • Per frame: up to 60 env steps (speed slider), ε-greedy, one-line Q update. Walls editable live.
  • Reduced motion: static frame after 40 pre-trained episodes; STEP still advances.
